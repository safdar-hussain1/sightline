How it works

Each turn of the wheel above is one answer from the model. This is how it gets there, on the clip above.

  1. Frames of the road

    The frame on screen and one taken just before it, cropped to the road and shrunk to the size the model reads. Together they show which way the view is moving.

  2. One ONNX graph, in your browser

    The trained network is a single ONNX file. It runs on this device, in WebAssembly, and no frame leaves the page.

  3. lessmore

    An angle, and where it looked

    Out come a steering angle and a heat map of where it looked: the brighter the spot, the more that part of the road counted.

It estimates the steering angle being applied from what it sees. It does not drive.

How accurate it is

Sightline is scored on minutes of driving it never trained on, against always steering straight on the same frames.

Test it the usual way, on shuffled frames, and the same kind of model looks better than it is on road it has not seen nearby.

Trained two ways, scored on the same frames

Each network is trained twice, once on shuffled frames and once with whole stretches of the drive held back, and both are scored on the very same frames.

A shuffled test makes the same kind of model look better than it is on road it has not seen nearby.

Further from the training frames

Each rung tests on frames further from anything the network trained on. A bar above the line beats always steering straight on the same frames; a bar below it does worse.

Baselines, on the same frames

Simple rules, scored on the very frames Sightline is tested on. Always steering straight, and always steering the training frames’ mean angle, never look at the road. Holding the last label and linear extrapolation read the answer stream, the driver’s own angle on the frames just before, which the model never sees.

The rules that read the answers are yardsticks here, not rivals.

What an earlier frame buys

SightlineNet sees the frame on screen and an earlier one. The same network trained on the frame on screen alone shows what the earlier frame is worth.

An earlier frame shows which way the view is moving.

Where it struggles

The test frames sorted by how hard the driver was turning: straight road, gentle curves and sharp ones.

On straight road, always steering straight is hard to beat.

The standard recipe

A PilotNet trained the widely copied way, scored here from its own weights.

Its arctangent output has a limit, and the drivers turned the wheel past it.

Where the numbers come from

Checked at export, and live

When each model was exported, onnxruntime was checked against PyTorch on every frame the page uses.

This browser’s answers are checked live against the same model run in Python.

How each split cuts the drive

Shuffled
Every frame is dealt at random to training, validation or test.
Blocked
The drive is cut into blocks, and frames are dropped either side of every boundary between a training block and a held-out one.
Later in the drive
The drive’s first part trains, the next validates and the last part tests.
Another day
Another drive, recorded on another day, scored by the networks trained with stretches held back.

The files

  • README what the repository holds, and how to run it
  • reports/summary.json the paired measurement, the ladder, the regimes and each network’s trainings
  • reports/runs each training run’s own report
  • reports/leakage.json the lookup table, and how close test frames sit to training frames
  • reports/legacy.json the standard-recipe PilotNet
  • reports/export.json the export check of the models the page runs
  • src/sightline/data/splits.py how each split cuts the drive

Every number in this view is read from results.json, which the repository generates from those reports. The model card says how the shipped model was trained, what it is for and where it falls short.
